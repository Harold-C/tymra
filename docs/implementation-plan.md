# Tymra 当前实施计划

更新：2026-10-07。实现、版本和最近运行证据只在[追踪表](traceability.md)维护；
本文件只列剩余工作及完成条件。以下是执行顺序，不产生采集、外部调用、生产写入或发布授权。
已完成步骤的变迁见[决策记录](decisions.md#文档与运行阶段变迁)。

## 当前判断

有界后台采集已上线；最近记录为 78 条公开计划与六条 OTA 计划全部开启。
Airbnb、Bookabach 及七个恢复公开来源已通过两轮精确试采，但恢复后的自然周期尚未全部验收。
全国数据深度和客户产品仍有独立门槛，不能据计划数量宣布完整产品可发布。

## 1. 核对恢复后的自然周期

先读实际 schedule、固定版本、预算、父 Job、CollectionRun、ArgusExecution 和交付记录，
不为验收重复访问来源。追踪表中的 nextRun 是当时记录，检查时须重新读回。

完成条件：

- 找到每个目标计划新生成的精确父 Job，核对幂等键、原 payload、一次尝试及成功来源 Run；
  不把人工试采或旧成功 Run 当作自然调度。
- 业务身份、日期、人数、币种和费用完整性符合来源合同；无可用记录与解析失败分别判断。
- 本地证据实际可读、哈希正确，持久交付及 ACK/410 可回查；验证后的数据仍可用于正常查询。
- 来源预算、并发、其他计划、队列、告警及运行版本保持预期；来源挑战、限流或解析失败时，
  保留记录并按现行机制暂停/人工处理，不重置计数、不移动既有验收起点来隐藏失败。
- 单个自然周期只证明该周期；长时稳定性、容量、全国代表性仍按后续范围验收。

## 2. 关闭工程安全与证据生命周期缺口

| 工作 | 完成条件 |
| --- | --- |
| 候选云端 CI 验收 | 已落地数据库 fail-closed、工作区边界/类型检查、空库 OTA delivery 及独立 Playwright job；按候选提交核对 GitHub Actions 的实际结果与失败证据。本地通过及 workflow 配置不代表云端已执行，`pnpm verify` 仍不包含 Playwright |
| Tymra 证据文件物理清理 | 按批准保留策略清理到期文件，关联数据库状态；未验证交付或仍需诊断证据不得提前删除；重试、缺文件、失败恢复与分类保留期有验收 |
| CAPTCHA 人工接管 | Admin 在同一 Argus Job/Page/BrowserContext 显示受保护的短期接管；完成人工验证后续跑，过期/复用/取消拒绝；证据与 ACK 完整 |
| 真实手工导入 | 获得范围明确的运营导出文件后，同一小样本运行两次，第二轮 immutable observation 零新增且原记录不覆盖，配置及计划不变 |

测试隔离与代码结构优化的本地验证见追踪表。其余事项仍需各自实施与验收，
不由结构重构、fixture 或文档更新视为完成。

## 3. 完成全国数据核心运行验收

按[全国差距表](traceability.md#全国数据核心差距)逐条关闭，不重新创建另一份需求清单。

1. 用非 demo 数据测量 17 Region 身份目录、真实公共信号深度及代表性 OTA 面板；
   记录分布、空缺和覆盖质量，不用 seed、计划启用或 Christchurch 样本替代。
2. 在明确来源与预算内验证地址和 Listing 两种按需模式；一个有效价格独立成功返回，
   附近价格不能归属到提交地址。监测任务必须保留目标模式和完整查询上下文。
3. 验证身份冲突/拆分、Listing 内容变化、历史追加不可变、时间与 lineage；
   真实覆盖、Freshness 和 Confidence 阈值用运行数据校准。
4. 检查每个来源的完整性、地域/时间精度及影响证据。School Sport 的地区级地点、
   缺失 venue/city 和事件 `PENDING_EVIDENCE` 不因采集成功自动补全。
5. 完成容量、成本、告警路由、故障停止和恢复演练，再判断全国后台验收是否通过。
   高频调度与扩大来源/预算另按实际范围授权。

## 4. 验收同版本客户产品并开放入口

目标仍是[产品合同](product/README.md)规定的同版本完整产品。
当前生产是 Admin-only 阶段；`DEPLOYED_HIDDEN` 只隐藏发现入口，不能代替访问控制或客户验收。

| 门槛 | 完成条件 |
| --- | --- |
| 登录、双模式与归属 | 独立密码注册/登录/退出；purpose-bound 邮箱验证；当前候选 EN/ZH 桌面/手机真实双模式结果；跨账户、未认证、失效会话拒绝；不产生额外 quota/Property slot |
| 四档会员与监测 | 权益、精确逐日范围/监测范围、配额、Benefit Group、取消/降级/宽限、历史保留与真实调度按商业合同核对 |
| 支付与高级能力 | Stripe 当前候选 Sandbox 生命周期及持久 webhook 对账；live Prices/Portal/Webhook、税务与生产验收另行完成。Export/API 独立开关及 Pro/Portfolio 依赖仍须成立 |
| 邮件与反滥用 | 真实通知到达、条件终态邮件与页面确认；HTTPS managed challenge 的拒绝/失败/误判与容量；日志和指标无秘密/PII |
| 浏览器与运营 | 当前候选完整路由、状态、键盘、reduced motion、EN/ZH、320/390px/桌面；告警、支持、隐私条款/保留期、备份恢复和回滚材料 |
| 生产入口 | 上述适用门槛通过并获对应开放授权后，调整 ingress/access mode，读回实际镜像、客户直接路由、权限、支付/通知业务结果 |

2026-08-12 Stripe Sandbox、旧会员 E2E 和 2026-09-25 隐藏入口检查作为带日期证据，
不替代当前生产的完整客户验收。长时 OTA soak 的历史人工豁免也不视为自然周期通过。

## 5. 持续优化

在数据正确性与真实运行门槛满足后，再按证据优化面板轮换、波动/成本调频、
lineage 查询、覆盖缺口排序及事件原始/标准分类拆分。新产品面、Partner API、
团队、PMS 写入及自动调价不属于当前已批准范围。
